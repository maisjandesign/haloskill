# Работа по восьми этапам

1. Запрос и запуск: вводные → паспорт проекта и задачи → проверка PM.
2. Ресерч: материалы и вопросы → выводы с источниками и неизвестными → проверка команды.
3. Workshop: пользовательский Client Research → пользовательский Script Writer → встреча с клиентом. Skill подготавливает исследование/сценарий; присутствие на встрече и транскрибация не обещаются.
4. Концепты: утверждённый бриф → направления и HTML → отбор дизайнером.
5. Презентация: концепты → презентация → решение клиента и правки.
6. Система и главная: выбранный концепт → токены, компоненты, реализация → проверка дизайнера и технического владельца.
7. Страницы: утверждённая система → страницы и реальные данные → проверка сценариев. CMS и интеграции определяются стеком проекта.
8. QA и передача: эталон и реализация → доказательства проверок, исправления, пакет передачи → приёмка командой.

Сохраняйте в проекте утверждённый бриф, журнал решений и ссылки на версии артефактов. Минимальная передача: входная версия; результат; проверено; открытые вопросы; владелец следующего шага. Не храните клиентские данные внутри переиспользуемых skills.

Рекомендуемые записи задачи: название, результат, критерий готовности, роль-владелец, зависимости, статус и ссылка на артефакт. До выбора трекера это документ; реальные карточки требуют подключения и проверки API.

Профиль проекта задаёт язык клиентских материалов, стек, хранилище документов, трекер, CMS, хостинг, ссылки Figma и критерии приёмки. Не выдумывайте эти значения из названия студии.
