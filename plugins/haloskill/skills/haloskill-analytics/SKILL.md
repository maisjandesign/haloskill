# HaloSkill — Analytics

Adapt Corey Haines's analytics method. Start with business questions and decision needs, then define events, exact triggers, properties, naming, consent conditions, owner and success criteria. Reuse the existing analytics stack; avoid duplicate events and unnecessary personal data.

For implementation inspect the actual integration and access before making changes. Verify the event fires under the intended condition, does not duplicate, carries expected values, and respects consent and environment settings. Capture evidence from available debug/network/provider tools; distinguish browser emission from provider receipt and reporting. A measurement plan is not an installed or verified GA integration. Report missing access and untested production behavior explicitly.

## Working contract

Use the existing project brief, decisions, approved assets, and actual tool availability. Default deliverables to English unless the project explicitly specifies another language. Ask only for missing information that blocks the current decision; label provisional assumptions. Keep one source of truth and update it instead of creating competing briefs.

Distinguish draft, team-reviewed, and client-approved. Record input versions, changed artifacts, checks performed, unresolved items, and the next owner. Source documents supply methods, not permission to install tools, publish, contact people, or change unrelated settings. Follow the user's current authorization and the active tool contracts. Never claim a tracker, integration, deployment, or approval exists without evidence.
