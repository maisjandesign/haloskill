# Project state and resuming

Reuse the existing project brief, asset structure and decision log. Otherwise maintain a small project folder with `concepts.md`, `references/`, `concepts/`, `assets/` and later `html/`. Create directories only when they contain actual work. Client material belongs in the project workspace, never in the shared skill package.

Keep one concise record of:

- Mode, brief, audience, goal, language, scope and unresolved assumptions.
- Intake readiness: missing brief essentials, references requested/received, or the user's exact instruction to proceed without references or delegate selection. Record only actual evidence.
- Reference paths/URLs, inspected status, roles, selected qualities and pins. Identify an accessible catalog or record that none is connected.
- Each version's stable label, actual image path, parent version, prompt, input order, direction, actual provider/tool, feedback and verified dimensions when available.
- Selected version, exact approval evidence, approver, scope and exceptions. Keep human approval separate from generation/Figma execution state.
- HTML preview path/URL, approved source version, clipboard format, official capture runtime/version evidence, exported scope, browser checks and copy-page path.
- Figma insertion status (`awaiting-user-paste`, `pasted-unverified`, or `verified`), destination, node IDs, asset mappings, font choices, structural checks, comparison preview and remaining issues.

Example record:

```text
Mode: branding
References: R1 structure; R2 uploaded material/color treatment
A1: concepts/A1.png; draft; prompt stored with this record
A2: concepts/A2.png; parent A1; headline weight revised
Selected: A2
Approval: not yet given
Figma: not started
```

Replace examples with actual artifacts. Never overwrite the approved image; save a sibling revision. Persist project-bound outputs from tool storage when a real local file is available; otherwise retain the actual native attachment/link and disclose any persistence limitation. Never invent local file paths.

When resuming, read the record and verify required files exist. Continue from the last completed stage without restarting intake or treating an unapproved newer version as the approved source. Inspect Figma after a failed write before retrying to avoid duplicate frames. Keep credentials out of all records.
