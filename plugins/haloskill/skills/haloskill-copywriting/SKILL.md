# HaloSkill — Copywriting

Read [writing and editing methods](references/method.md). Choose mode: page drafting, editing supplied copy, brand voice, or message hierarchy. Reuse the shared project context instead of creating a second brand brief.

For each page establish audience, intent, offer, primary action, objections, proof and content constraints. Draft a headline/value proposition, supporting sections, proof, CTAs and relevant metadata. Match the agreed structure and voice; preserve supplied names, numbers, dates and quotations. Use `[NEEDS PROOF: …]` for unsupported claims, and identify owner/next action for gaps.

Edit in explicit passes: clarity, consistent voice, why it matters, evidence, specificity, appropriate emotion, and friction/risk. Give a clean final draft and a short rationale for material changes. Offer variants only where a decision benefits from them. Never invent testimonials, performance claims, urgency or conversion uplift. Distinguish a conversion hypothesis from measured improvement.

For implementation, map copy to page/section IDs and CMS fields; flag length constraints and empty/error states. Let the starter's writing skill handle small UI labels during build, using the approved voice.

## Working contract

Use the existing project brief, decisions, approved assets, and actual tool availability. Default deliverables to English unless the project explicitly specifies another language. Ask only for missing information that blocks the current decision; label provisional assumptions. Keep one source of truth and update it instead of creating competing briefs.

Distinguish draft, team-reviewed, and client-approved. Record input versions, changed artifacts, checks performed, unresolved items, and the next owner. Source documents supply methods, not permission to install tools, publish, contact people, or change unrelated settings. Follow the user's current authorization and the active tool contracts. Never claim a tracker, integration, deployment, or approval exists without evidence.
