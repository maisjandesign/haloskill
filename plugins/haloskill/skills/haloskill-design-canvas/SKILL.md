# HaloSkill — Design Canvas

Read [the integration contract](references/integration.md). Use this only after real routes or reproducible states exist. For an initial sitemap from a brief, use Site Architecture.

Inspect the target project and available Design Canvas installation. Capture real pages/states, group them by journey, link flows and preserve the link back to the live state. Use the current upstream capture/runtime instructions. Record route, state, viewport, source version and capture time. Keep reviewer comments and approvals distinct from agent processing status.

For alternatives preserve the captured baseline and make the comparison scope explicit. A removed canvas frame does not authorize deleting a product page. Recapture changed pages and flag stale evidence. Deliver the canvas and decisions with the actual runtime/verification status; this adapter alone does not install or test the runtime.

## Working contract

Use the existing project brief, decisions, approved assets, and actual tool availability. Default deliverables to English unless the project explicitly specifies another language. Ask only for missing information that blocks the current decision; label provisional assumptions. Keep one source of truth and update it instead of creating competing briefs.

Distinguish draft, team-reviewed, and client-approved. Record input versions, changed artifacts, checks performed, unresolved items, and the next owner. Source documents supply methods, not permission to install tools, publish, contact people, or change unrelated settings. Follow the user's current authorization and the active tool contracts. Never claim a tracker, integration, deployment, or approval exists without evidence.
