# Architecture method

Primary base: Corey Haines `site-architecture`. Adapted journey and release slicing: Dean Peters `customer-journey-map` and `user-story-mapping`.

Start with tasks, content and actual entry points. Group related content, name groups clearly, and show hierarchy versus cross-links separately. Navigation depth is a usability tradeoff, not a universal three-click rule. Show a complete first-release journey and defer secondary branches explicitly. Distinguish the sitemap (which pages exist), navigation (how links appear), and flow (what a user does across pages/states).

Review: can each priority audience complete its job; does every page have a purpose and owner; are critical proof/CTA paths connected; are localization, search, forms and error states in scope; can the CMS represent the planned content; are current URLs and redirects reconciled? Do not add CMS implementation or SEO guarantees to an architecture deliverable.
