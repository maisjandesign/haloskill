# HaloSkill — Workshop Script Writer

Write a conversation the facilitator can read aloud. Assume no access to earlier chats. Default to English for spoken text; use the user's language for discussion. A request to prepare the workshop means a prepared script, not a completed strategy.

## Read before drafting

Read [the user's original script and voice guidance](references/facilitator-voice.md) before writing spoken text. Before drafting any stage, also read [the stage map and complete three-question stage example](references/workshop-patterns.md). Follow its visible structure as well as the voice reference. These are the portable context; do not merely mention them or rely on generic “plain English”. A new user-supplied voice reference takes precedence.

Use the supplied client brief, sales transcript and research. If missing, obtain research or use haloskill-workshop-client-research. If the user provides a skill folder, use that version and its references rather than silently substituting an installed copy.

## Build the conversation

1. Separate settled answers from decisions still open. Do not ask sales questions again. Use known answers to introduce the next unresolved choice.
2. Plan six stages: website goal; visitor situation; reasons to choose; questions and objections; voice; discovery and action. The reference explains the purpose and decision for each.
3. Assign each research fact one main use. Prepare a specific observation, a modest interpretation, and one clear question. Keep this logic internal: output the actual words to say.
4. Open with a brief purpose and how the conversation will work. Close by checking decisions and agreeing owners for missing inputs. Keep scope checks brief; CMS, migration inventories, contracts and technical audits belong in preparation notes or another meeting unless they change the content decision.

## Spoken output

- Use stage headings, short spoken transitions and short paragraphs with natural pauses. Within every stage, show three numbered question blocks (1, 2, 3), each with its own setup, one main question and one adjacent **Follow-up**. A brief stage purpose can precede them. No Structure, Example, Universal question labels or source links; do not repeat a question as both heading and body. Put evidence and citations in a separate research document.
- Match the reference's conversational rhythm, not just its vocabulary. Explain why a question matters before asking it. Do not reduce the script to a list of questions or stack several questions in one sentence.
- Default to exactly three main question blocks per stage, each addressing a distinct decision. Prepare one short follow-up for each block; ask it live only if that point remains unclear. This means three prepared follow-ups per stage, not three extra required questions. Do not collect them at the end or add a bank of probes. Change this structure only when the user requests it; shorten setups or adjust timing instead of silently dropping a block.
- Every prepared passage must work before answers exist. No invented prior answers, obligatory improvisation, or assumed “Perfect” replies. Adapt or skip live when already answered.
- Prefer a client-specific hypothesis open to correction. A well-known brand or client-selected reference may clarify a choice, sparingly. Never use unfamiliar companies as decorative spoken examples.

## Final read-through

Read it as one conversation: simple English for a non-native speaker, varied transitions, no repeated preambles, one answerable question at a time. Check it against both references: the original voice and the complete stage example. Confirm every stage has three visibly separate blocks, each with its own follow-up. Use realistic discussion timing; do not pad the script to fill it. Deliver the requested format without adding internal preparation machinery to the spoken text.
